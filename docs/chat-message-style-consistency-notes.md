# Chat Message Style Consistency Notes

## 背景

当前聊天区已经形成了较稳定的视觉语言，但这种一致性更多来自少量公共外壳组件和大量人工对齐，而不是完整的共享内容样式基础设施。

这在 agent orchestration 第一轮实现中暴露得比较明显，尤其是执行型代理卡片的折叠态、展开态、标题栏背景、内容区背景、边框、复制按钮、section 内容块等区域，反复出现“局部看似正确，但整体仍与现有聊天区风格脱节”的问题。

## 当前现状

### 已有统一部分

- `MessageItem.vue`
  - 提供消息列表中的统一外壳
  - 负责头像、左右布局、顶部统计、surface 模式、消息间距等

- `chatTheme`
  - 提供部分主题约束，例如 `messageSurface`、`avatarMode`、`statusStyle`、`messageSpacing`

### 缺失的统一部分

目前没有一套真正通用的“消息内容块”基础组件或样式层，导致以下内容仍主要由各消息组件自行实现：

- 标题栏背景
- 内容区背景
- section 容器
- section label
- section content wrapper
- copy button
- 折叠摘要行
- 内部滚动容器
- 结果面板

也就是说，当前系统更接近：

- 外层壳部分统一
- 内层内容块各自实现
- 一致性依赖人工模仿和局部复制

而不是：

- 外层壳统一
- 内层内容块也有统一基础设施

## 这轮实现中暴露出来的典型问题

### 1. 特殊消息一旦脱离现有内容组件，就很容易失真

执行型代理卡片一开始使用独立的 header / section / body 样式后，立刻出现：

- 标题栏背景与现有 tool use 不一致
- 内容区背景不一致
- section 的边框、间距、滚动条风格不一致
- 复制按钮样式丢失

### 2. 视觉一致性目前主要靠“对齐已有组件”

目前要让一个新消息块看起来正确，最有效的办法往往不是“套统一基础组件”，而是：

- 对照 `ToolUseMessage.vue`
- 对照 `MessageItem.vue`
- 人工复制 section 结构和局部样式

这种方式短期可行，但长期不稳定，后续新增更多特殊消息时会反复出现相同问题。

### 3. 样式 token 没有被系统化抽离

像下面这些视觉语言虽然已经在界面里形成了事实标准，但还没有被提炼成共享抽象：

- 工具卡片标题栏底色
- 内容区底色
- section label 的字号/颜色/字距
- `section-copy-btn` 的交互与显隐
- 结果面板滚动区样式
- 深色内容块的边框和圆角节奏

## 后续改进方向

建议后续单独安排一轮“聊天消息样式基础设施收口”，目标不是局部修修补补，而是补齐一层真正可复用的共享内容块体系。

### 建议抽离的基础能力

- 统一的消息内容 section 组件
- 统一的 copy button 组件
- 统一的 section label / section body / result panel 样式
- 统一的滚动容器样式
- 统一的工具消息 header token
- 统一的深色内容块背景、边框、圆角、hover 节奏

### 建议原则

- 新增特殊消息时，优先复用共享内容块
- 不再鼓励在单个消息组件中重新发明 section 结构
- “视觉一致性”应由基础设施保证，而不是靠实现者手工模仿

## 与 agent orchestration 的关系

执行型代理卡片已经证明：

- orchestration 本身不是主要难点
- 真正容易反复返工的是聊天消息内容样式基础设施不足

因此，后续如果继续扩展：

- 协作型代理多视图
- 分屏消息视图
- 执行型代理更复杂的展开布局

建议优先补齐样式基础设施，否则每新增一种消息形态都会再次遭遇一致性问题。

## 当前结论

这个问题不是单纯的“某几个 CSS 没调对”，而是一个明确的前端基础设施缺口：

- 当前聊天系统有统一外壳
- 但缺少统一内容块体系

后续应将其视为一个独立的架构/设计系统问题处理，而不是继续按局部样式问题逐处修补。
